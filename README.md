# P2PV

Своя локальная сеть через интернет. Открытая замена Radmin VPN.

Вы вводите имя сети и пароль — друзья вводят те же самые. Все оказываются в
одной виртуальной локальной сети и видят друг друга так, будто сидят в одной
комнате с одним роутером. Дальше работает всё, что работает по локальной сети:
Minecraft, Terraria, Stardew Valley, старые игры без своих серверов, общие папки.

Трафик идёт **напрямую между компьютерами** — сервер нужен только чтобы вы друг
друга нашли. Если прямой путь не пробивается (строгий NAT у провайдера), трафик
идёт через сервер-ретранслятор, но расшифровать его сервер не может. Об этом
ниже, в разделе про безопасность.

## Как это выглядит

```
$ p2pv join my-friends secret123
Joining "my-friends" via 203.0.113.10:27241...
interface P2PV up, virtual IP 100.88.0.2
peer DESKTOP-VASYA (100.88.0.3) is online
encrypted channel with DESKTOP-VASYA established
direct path to DESKTOP-VASYA via 95.24.11.8:41221

-- my-friends -- this machine: 100.88.0.2 (DESKTOP-VLAD)
   100.88.0.3      DESKTOP-VASYA        direct
```

`direct` — трафик идёт напрямую. `relayed` — через сервер. Играть можно в обоих
случаях, разница только в задержке.

## Установка на Windows

Есть три варианта одного и того же: `P2PV.exe` — окно, `p2pv-tray` — только
иконка в трее, `p2pv` — командная строка. Если не уверены, берите окно.

1. Скачайте `p2pv.exe` (или соберите: `go build ./cmd/p2pv`).
2. Положите рядом `wintun.dll` — это драйвер виртуального адаптера:

   ```powershell
   .\scripts\get-wintun.ps1
   ```

   Скрипт скачивает официальный wintun 0.14.1 и **проверяет SHA256** — если хеш
   не совпал, установка прерывается. Устанавливать ничего не нужно: это просто
   DLL рядом с exe.

3. Запускайте **от администратора**. Создание сетевого адаптера требует прав —
   это ограничение Windows, обойти его нельзя.
4. Укажите координатор. Сервера по умолчанию в этой сборке нет: поднимите свой
   (раздел «Свой сервер») или используйте тот, который вам дали.

```powershell
p2pv join my-friends -server ваш-сервер:27241
```

Пароль спросит и не покажет при вводе. После первого раза сеть запоминается, и
пароль можно не вводить.

## Установка на Linux

```bash
go build ./cmd/p2pv
sudo ./p2pv join my-friends -server ваш-сервер:27241
```

`sudo` — по той же причине: создание tun-интерфейса.

## Команды

```
p2pv join <сеть> [пароль]   подключиться и оставаться в сети
p2pv networks               список запомненных сетей
p2pv forget <сеть>          забыть сеть
p2pv id                     показать идентификатор этого устройства
```

Флаги для `join`:

| Флаг | Что делает |
|---|---|
| `-server host:port` | адрес координатора (в этой сборке обязателен) |
| `-iface name` | имя интерфейса (по умолчанию `P2PV`) |
| `-lan-discovery` | пустить multicast в туннель — см. ниже |
| `-v` | подробный лог |

## Как играть в Minecraft

**Надёжный способ — Direct Connect.** Работает всегда, ничего настраивать не надо.

Хост открывает мир в LAN (`Esc` → «Open to LAN»), смотрит свой адрес в таблице
`p2pv` (например `100.88.0.2`) и порт, который показал Minecraft. Остальные идут
в `Multiplayer` → `Direct Connection` и вводят `100.88.0.2:25565` (порт — тот,
что показал Minecraft, он каждый раз разный).

Для выделенного сервера — то же самое, только порт всегда `25565`.

**Автоматический поиск в списке «Сети LAN»** требует флага `-lan-discovery`:

```powershell
p2pv join my-friends -lan-discovery
```

Minecraft объявляет открытые миры по multicast на `224.0.2.60:4445`. Чтобы такие
объявления уходили в туннель, нужен маршрут для всего диапазона `224.0.0.0/4` — а
это **весь** multicast машины. Пока флаг включён, ваш компьютер перестаёт видеть
принтеры, колонки и Chromecast в настоящей локальной сети (mDNS и SSDP уходят в
туннель вместе с игровыми объявлениями).

Поэтому флаг выключен по умолчанию: Direct Connect работает без него и ничего не
ломает. Включайте, если удобство важнее обнаружения устройств в реальной сети.

## Окно (P2PV.exe)

Если консоль не нужна — есть обычное окно, как у Radmin VPN. Это `P2PV.exe`:

```powershell
build\P2PV.exe
```

Windows покажет **запрос UAC** — окно сразу просит права администратора, потому
что без них не создать сетевой адаптер. Лучше один запрос при запуске, чем
ошибка после нажатия «Подключиться».

Вводите имя сети и пароль, нажимаете «Подключиться» — в таблице появляются
остальные участники с их адресами. Столбец «Соединение» показывает `напрямую`
или `через сервер`. Двойной клик по участнику копирует его адрес, правый клик —
адрес сразу с портом Minecraft (`:25565`), то есть готовую строку для Direct
Connect.

Запомненные сети подставляются в выпадающий список, и для них пароль вводить не
нужно. Галочка «Поиск игр по сети» — тот же `-lan-discovery`, с той же
оговоркой про multicast (см. выше).

Внизу — журнал движка. Он там не для красоты: у окна нет консоли, и если не
хватает прав или рядом нет `wintun.dll`, текст ошибки видно именно здесь (и в
диалоге).

Закрытие окна крестиком **не разрывает соединение**, пока вы в сети — окно
уходит в трей, чтобы случайный клик не выкинул всех из игры. Выйти полностью —
через меню иконки в трее.

`P2PV.exe` нужен только под Windows. На Linux используйте `p2pv` или
`p2pv-tray`.

## Иконка в трее

То же самое, но без консоли — как в Radmin VPN:

```powershell
p2pv-tray                      # подключиться к единственной запомненной сети
p2pv-tray my-friends           # к конкретной запомненной
p2pv-tray my-friends secret123 # к новой
```

Цвет иконки показывает состояние: зелёная — все на прямом соединении, жёлтая —
кто-то идёт через relay, серая — никого нет онлайн. В меню видны участники и их
адреса; клик по адресу копирует его в буфер обмена — это то, что нужно для
Direct Connect.

У трея нет консоли, поэтому пароль он не спрашивает: либо сеть уже запомнена
(`p2pv join` один раз), либо пароль передан аргументом. Ошибки — отсутствие прав
администратора или `wintun.dll` — показываются прямо в меню, а не только в логе.

Флаги те же, что у `p2pv join`.

## Свой сервер

Координатора по умолчанию в этой сборке нет — поднимите свой. Это один
бинарник и один UDP-порт, ничего больше.

```bash
GOOS=linux GOARCH=amd64 go build -o p2pv-server ./cmd/p2pv-server
scp p2pv-server root@ваш-сервер:/usr/local/bin/
```

Юнит systemd (`/etc/systemd/system/p2pv-server.service`):

```ini
[Unit]
Description=P2PV coordinator and relay
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
ExecStart=/usr/local/bin/p2pv-server -listen :27241 -state /var/lib/p2pv/state.json
Restart=always
RestartSec=5

# Серверу не нужны никакие права, кроме одного UDP-порта.
DynamicUser=yes
StateDirectory=p2pv
NoNewPrivileges=yes
ProtectSystem=strict
ProtectHome=yes
PrivateTmp=yes

[Install]
WantedBy=multi-user.target
```

```bash
systemctl enable --now p2pv-server
```

Нужен один открытый UDP-порт (по умолчанию 27241). Клиенты подключаются так:

```
p2pv join my-friends -server ваш-сервер:27241
```

Флаги сервера: `-listen`, `-state`, `-subnet` (база для виртуальных адресов, по
умолчанию `100.88.0.0`), `-v`.

## Безопасность

Главное свойство: **сервер не может прочитать ваш трафик**, даже если он ваш
собственный, даже если его взломали, даже если он записывает всё подряд.

Как это устроено:

- Из имени сети получается её идентификатор: `NetworkID = BLAKE2s(имя)`.
- Из пароля — ключ сети: `PSK = Argon2id(пароль, соль=NetworkID)`. Argon2id
  выбран специально: подбор пароля по хешу стоит памяти, а не только времени.
- Серверу отправляется не ключ, а `Verifier = BLAKE2s(PSK)` — односторонний хеш.
  Сервер проверяет, что вы знаете пароль, но сам получить `PSK` из `Verifier` не
  может. Значит, не может ни подделать участника, ни встроиться в середину.
- Между парами компьютеров поднимается Noise **IKpsk2** (X25519 +
  ChaCha20-Poly1305 + BLAKE2s) на свежих эфемерных ключах. Идентификатор сети
  входит в рукопожатие как prologue — рукопожатие нельзя переиграть в другой сети.
- Защита от повторов: явный 64-битный счётчик как nonce и скользящее окно на 64
  пакета. Окно сдвигается **только после** успешной проверки AEAD, поэтому
  подделанный пакет не может вытеснить настоящие.

Проверки, которые делает клиент и которые стоит назвать прямо:

- пир с чужим идентификатором отвергается (`ID ≠ BLAKE2s(его ключ)`);
- рукопожатие с ключом, отличным от того, что пришёл в списке пиров, отвергается;
- пакет с IPv4-адресом источника, не равным виртуальному адресу этого пира,
  отбрасывается — один участник сети не может выдать себя за другого.

Что сервер всё-таки видит: кто с кем и когда обменивается пакетами, и их размер.
Это неизбежно для любого координатора. Содержимое — нет.

Локально хранится: `identity.key` (постоянный ключ устройства, права 0600) и
`networks.json` — в нём **PSK, а не пароль**. На Windows это
`%AppData%\P2PV\`, на Linux — `~/.config/P2PV/`. Точный путь покажет `p2pv id`.

## Как это работает внутри

```
        ┌──────────────┐
        │  координатор │  знает: NetworkID, Verifier, кто онлайн, адреса
        │   + relay    │  не знает: PSK, содержимое пакетов
        └──────┬───────┘
               │ UDP 27241 (регистрация, список пиров, пробивание NAT)
       ┌───────┴────────┐
       │                │
   ┌───▼───┐        ┌───▼───┐
   │   A   │◄══════►│   B   │  Noise IKpsk2, напрямую если получилось
   └───────┘        └───────┘
```

1. Клиент регистрируется на координаторе, получает стабильный виртуальный адрес
   (`100.88.x.y`) и список участников с их публичными ключами.
2. Клиенты пробивают NAT навстречу друг другу (UDP hole punching). Координатор
   при этом выступает в роли STUN-подобного наблюдателя внешних адресов.
3. Если не получилось — трафик идёт через relay на том же порту.
4. **Апгрейд пути на живую:** если прямой путь появился позже, сессия
   переключается на него без нового рукопожатия. Сессии привязаны к пирам, а не
   к путям — поэтому переключение не рвёт соединение и не теряет счётчик.

MTU туннеля — 1400. Пакет полного размера через relay занимает 1478 байт на
проводе, что помещается в типичные 1500 с запасом 22 байта.

Широковещательные пакеты (`255.255.255.255` и broadcast подсети) и multicast
рассылаются программно всем пирам, с которыми есть сессия — именно так игры
находят друг друга в локальной сети.

Структура проекта:

```
cmd/p2pv           клиент (CLI)
cmd/p2pv-tray      клиент с иконкой в трее
cmd/p2pv-gui       клиент с окном (только Windows)
cmd/p2pv-server    координатор и relay
cmd/p2pv-probe     отладочный отправитель/слушатель tcp/udp/multicast
internal/proto     формат пакетов
internal/netid     имя+пароль → NetworkID, PSK, Verifier
internal/session   Noise IKpsk2, шифрование, защита от повторов
internal/client    движок клиента: устройство, сокет, маршрутизация
internal/server    реестр пиров, relay, брокер пробивания NAT
internal/device    виртуальный адаптер (Wintun / tun) и маршрут multicast
internal/gui       окно: форма подключения, таблица участников, журнал
internal/tray      иконка в трее и меню
internal/store     ключ устройства и запомненные сети
winres/            иконка и манифест Windows (права администратора, DPI)
```

`internal/device` спрятан за интерфейсом `Device` — это оставляет возможность
добавить L2/TAP-бэкенд, не трогая обработку пакетов.

## Тесты

Юнит-тесты (рукопожатие, неверный пароль, окно повторов, маршрутизация,
арифметика MTU):

```bash
go test ./...
```

Сквозной тест на одной Linux-машине — два клиента в разных сетевых
пространствах имён, что заменяет два разных NAT:

```bash
sudo ./scripts/netns-test.sh
```

Он проверяет обе фазы: с `ip_forward=0` прямой путь невозможен и трафик обязан
идти через relay, потом `ip_forward=1` — и клиенты должны сами перейти на прямой
путь, не разрывая сессию. Плюс TCP, broadcast и multicast.

Последний прогон:

```
PASS relay ping               (0.481 ms средн.)
PASS direct ping              (0.293 ms средн., та же сессия)
PASS upgraded to a direct path
PASS TCP stream
PASS broadcast fan-out
PASS multicast fan-out
```

Скрипт сохраняет и восстанавливает `ip_forward` и убирает за собой namespace'ы.

## Сборка

```bash
go build ./cmd/p2pv                                        # под текущую систему
GOOS=linux GOARCH=amd64 go build -o build/p2pv-linux ./cmd/p2pv
GOOS=windows GOARCH=amd64 go build -o build/p2pv.exe ./cmd/p2pv
```

Cgo не нужен, кросс-компиляция работает без дополнительных инструментов.

Окно собирается отдельно, потому что ему нужны ресурсы Windows — иконка,
манифест и версия:

```bash
go install github.com/tc-hib/go-winres@v0.3.3
go-winres make --out cmd/p2pv-gui/rsrc          # из winres/winres.json
go build -ldflags="-H windowsgui" -o build/P2PV.exe ./cmd/p2pv-gui
```

`-H windowsgui` убирает окно консоли. Манифест из `winres/` обязателен, и не
только ради запроса прав: без зависимости от Common Controls 6.0.0 библиотека
окон падает при создании окна («TTM_ADDTOOL failed»). Готовый `.syso` лежит в
репозитории, так что для обычной сборки `go-winres` не нужен — только если вы
меняете иконку или манифест.

## Откуда название

P2PV — это третий подход к одной и той же идее. Первые два жили как плагин к
серверу Minecraft: плагин раздавал участникам виртуальные адреса `10.0.0.x` и
рассылал список пиров. Координация там была сделана правильно, но передачи
данных не было вовсе — адреса присваивались адаптеру Microsoft KM-TEST Loopback,
который по своей природе не может отправить пакет в сеть. И сама сеть
существовала только пока запущен сервер Minecraft.

Здесь от той идеи осталось название и модель «имя сети + пароль». Всё остальное
переписано: настоящий виртуальный адаптер, шифрование между участниками,
пробивание NAT с relay как запасным вариантом и отдельный сервер, которому не
нужен Minecraft.
